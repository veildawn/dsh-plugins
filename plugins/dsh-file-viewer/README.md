# dsh-file-viewer

在 DeepSeek Harness 里查看工作区文件：左侧目录树，右侧按格式渲染内容。

支持的格式：

| 格式 | 渲染方式 |
| --- | --- |
| 代码、配置、纯文本 | 语法高亮（复用 DSH 内置 shiki，26 种语言），带行号，按 500 行分页 |
| Markdown | 预览（GFM + 公式）与源码切换 |
| JSON | 可展开的结构树与源码切换 |
| 图片 | PNG、JPEG、GIF、WebP、AVIF、BMP、ICO、SVG |
| PDF | 交给浏览器内置阅读器（可搜索、翻页、缩放） |
| Excel | `.xlsx` / `.xlsm` / `.xls`，工作表标签 + 表格 |
| Word | `.docx` / `.doc`，转 Markdown / 提取文本后渲染 |
| 其他二进制 | 显示文件信息，可用本地程序打开 |

## 安装

```bash
dsh plugin --profile web add <release-tgz-url>
```

### 重启生效

`@deepseek-ai/dsh` 官方 CLI 本身没有 `service` 子命令，执行 `dsh service restart` 会报错。请使用本仓库自带的控制脚本：

- **macOS / Linux**：
  ```bash
  ./scripts/dsh-web.sh restart
  ```
- **Windows**：
  ```powershell
  .\scripts\dsh-web.ps1 restart
  # 或 cmd:
  scripts\dsh-web.cmd restart
  ```

装完确认 profile 的 `dsh.profile.bundles` 里有 `dsh-file-viewer`，否则插件不会加载。

## 使用

- **唤起入口**：
  - **PC 端输入框工具栏**：严禁悬浮按钮；文件查看器按钮干净聚焦地内嵌于输入框操作条左侧（与快捷命令 `+` 号、权限模式标签并列），在**新建空白会话**（居中的 Hero 输入框）与**常规对话**（底部常驻输入框）全场景始终清晰可见且不遮挡内容；
  - **移动端原生集成**：严禁悬浮按钮；手机端通过底部工作区工具箱菜单（四宫格图标 -> “📁 文件查看器”）或顶部适配栏原生唤出；
  - **会话中点击文件**：在会话回复（变更文件卡片、产物交付卡片、行内代码引用等）中点击任何文件路径，自动唤起文件查看抽屉并直接选中预览该文件。
- `Esc` 或点击抽屉外部遮罩关闭。

**桌面端接管说明**：桌面版宿主判定自己能在系统里打开路径，因此会在文件路径与更改卡片旁额外渲染原生「在应用中打开」按钮，更改卡片还会走 `/api/changes.open` 这条直接交给操作系统的路由。插件在这两处都会先接管，改为唤起文件查看抽屉：原生打开按钮按 `data-open-path-open` 识别，更改卡片打开路由则从 URL 里的 `sessionId / seq / index` 回查文件路径。取不到路径时一律放行，仍按宿主原方式打开，不会出现点了没反应。

顶部可切换工作区、刷新、显示或隐藏点文件。目录在树中原地展开，子级首次展开时才加载。

### 多标签页

右侧内容区是一个标签栏，打开的文件、提交和工作区改动各自占一个标签，切换标签即切换内容，不会互相覆盖：

- **新建标签**：在文件树里点击文件、在 Git 面板里点击提交或某条工作区改动，都会新开一个标签；点击**已经打开**的文件不会新建标签，而是切回原来那个。
- **关闭**：标签右侧的 `×` 关闭该标签。关掉当前标签后落到右邻标签（没有则左邻）；关掉最后一个标签时内容区回到「未打开文件」，并把焦点交还左侧栏。
- **关闭抽屉再打开是「隐藏」而不是「重来」**：已打开的标签、当前选中的标签、左侧停在文件还是 Git 面板、树里展开的目录，都原样保留；重新打开时还会把树里正在显示的目录重读一遍，所以内容是新的、形状是你上次留下的。`Esc`、点遮罩、手机返回手势都只是隐藏。
- **只有真正换了项目才会重置**：切到另一个工作区（根目录）时，标签、展开集、内容区一起清空——标签里记的路径只对打开它的那个根目录有意义，留着会指到同名的另一个文件。

### 标签页与文件树联动

左侧目录树会**始终高亮右侧当前标签打开的那个文件**，两半永远描述同一个文件：

- **高亮跟随标签，不跟随点击**：换一个标签、用 `←` / `→` 在标签栏里移动、关掉当前标签落到邻居，左侧的高亮都立刻跟过去。它不是"记住最后点过的那一行"，所以从 Git 面板、会话里的文件链接、`@` 引用等任何入口打开的标签都会同步。
- **打开即高亮，不等文件读完**：高亮取自标签自己记录的路径，而不是文件读取完成后才有的元数据。刚点开、内容还在加载时那一行就已经亮了，不会出现"标签开了、树没反应"的空窗。
- **自动展开到目标文件**：标签指向的文件可能藏在收起的目录里，甚至那个目录还从没被列过。树会自动展开沿途每一级目录（并请求缺失的列表），让这一行真正出现；它只**加**展开项，不会关掉你已经打开的目录。
- **自动滚动到可见位置**：目标行不在可视区时，树会把它滚到中间；已经在可视区内就不动，避免和手动滚动打架。遵循系统的"减少动态效果"设置（此时直接跳转、不做平滑动画）。
- **只高亮工作区里的真实文件**：Git 提交标签、工作区改动的 diff 标签、以及从提交历史打开的某个版本（其路径在磁盘上可能已不存在）都不在目录树里，因此左侧不标记任何行，不会假装那是一个正在查看的工作区文件。
- **没有打开的标签就没有高亮**：关掉最后一个标签后，左侧不再留一行亮着——高亮被当作"这个文件正开着"的陈述，不能比事实多停留。

高亮本身由三部分构成，保证在浅色与深色主题下都读得出来：整行底色、左侧 2px 品牌色竖条、行内文字加粗。键盘聚焦时的焦点框与"当前文件"分开，鼠标点完不会留下和选中态抢眼的方框。

标签上右键（键盘为 `Shift+F10` 或菜单键）打开四项菜单：

| 菜单项 | 作用 |
| --- | --- |
| 刷新当前 | 重新读取该标签的内容：文件重读元数据与内容，提交与工作区改动重跑对应的 Git 读取。**只刷新这一个标签，其余标签原样不动。** |
| 关闭当前 | 关闭右键的这一个标签 |
| 关闭其它 | 只保留右键的这一个标签（只剩一个标签时该项置灰） |
| 关闭所有 | 关闭全部标签 |

文件树支持**右键上下文菜单**与单项 `@` 快捷按钮：
- **复制相对路径**：复制文件/目录相对于工作区根目录的路径；
- **复制绝对路径**：复制文件/目录在操作系统中的完整物理路径；
- **引用到输入框 (@)**：将文件/目录以 `@path` 格式插入对话输入框。**支持在输入框当前光标处精确追加**，并带有自适应空格规整；绝不覆盖或冲掉输入框中用户已输入的已有内容；
- **文件下载到本地**：
  - **顶部工具栏**：选中文件后，标题栏常驻提供 `⬇️` 下载图标按钮，一键将当前预览文件另存到本地；
  - **右键上下文菜单**：在文件树右键点击任意文件，选择 `⬇️ 下载文件` 即可直接提取；
  - **二进制/超大文件兜底区**：对于无法在线渲染的二进制文件或大文件，提示卡片内提供“下载到本地”按钮，完美解决 Web/远程模式下无法提取文件的痛点。
- **删除文件 / 目录**：菜单最底部，与上面的安全项之间有一条分隔线，文字与图标常驻红色。

### 删除

删除**必须先确认**，确认框会明确写出要删的是哪一个：

```
┌ 删除文件？ ────────────────────┐
│  a.txt                        │
│  src/a.txt                    │
│  该文件将被永久删除，无法撤销。   │
│                    [取消] [删除] │
└───────────────────────────────┘
```

- **目标名 + 相对路径都显示**：树里可能有多个同名文件散在不同目录，只写「a.txt」不足以让人确认删的是哪一个。
- **目录是更强的警告**：「该目录及其中的所有内容都会被永久删除」，并且宿主端只有带 `recursive` 才肯执行——不带就被拒绝（`is-a-directory`），免得一个以为在删文件的调用把整棵子树带走。
- **默认焦点在「取消」上**，`Esc` 也取消。删除按钮是红的，但一次反射性的回车不会触发它。
- **根目录永远删不掉**：`path` 为空、`.`、`./`、`sub/..` 这类指向根目录的写法一律拒绝（`cannot-delete-root`）。这个判断在写第一版时漏了 `./`，是测试抓出来的。
- **越界路径一律拒绝**：和所有读取走同一道闸（`resolveInRoot`）——先做绝对路径与 `..` 的形状检查，再用 `ctx.fs.contains` 比对规范化后的身份，符号链接绕不出去。
- **删完把界面收拾干净**：指向该路径（或该目录内）的标签页会被关闭，树里正在显示的目录重新读取，Git 徽标重算——否则会留下一个打开着、但文件已经不存在的标签页。

**实现说明**：宿主的 `dsh-fs` 服务是只读的（只有 `writeText` / `editText`，没有任何 unlink），所以删除是本插件唯一一处直接用 Node `fs` 碰磁盘的地方。正因为绕开了宿主的抽象，上面那些校验是承重墙而不是防御性代码。删除失败时只回传原因码，不回显绝对路径——fs 错误里带着宿主路径，而这个插件其余部分一直避免泄露它。

### 调整宽度

两处宽度可以分开拖动，互不影响：

- **面板整体宽度**：拖动抽屉**左边缘**（鼠标移到左侧边框会出现高亮提示条）。抽屉贴在窗口右侧，所以**往左拖是加宽**、往右拖是收窄。最小 420px，最大不超过窗口宽度——上限是窗口本身，避免把面板自己的关闭按钮推出屏幕。双击手柄恢复默认宽度（`min(64vw, 1100px)`），拖动结果会记住。
- **侧栏宽度**：拖动文件树与预览之间那条分隔线，调整的是侧栏占面板内部的比例；双击恢复默认 280px。

两个宽度分别持久化（`dsh-file-viewer.shell-width` 与 `dsh-file-viewer.tree-width`），所以调宽面板不会改变侧栏比例。

### 调整阅读字号

内容区工具栏右侧有一个字号步进器（`A-` / `A+`，中间显示当前值），用于把正在读的内容放大或缩小。范围 11–24px，步长 1px，取值记住在本地（`dsh-file-viewer.font-size`）。

**只对渲染文本的视图出现**：纯文本/代码、Markdown、JSON。图片、PDF、Excel、Word、二进制文件没有这个按钮——它们各自有自己的缩放，或者本来就不是可调排版的正文。

三处文本视图**都会跟随**这个设置：

| 视图 | 字号生效方式 |
| --- | --- |
| 源码 / 代码（宿主 `ReadBlock`） | 重声明代码卡的 `font:` 简写 |
| Markdown 预览 | 重声明预览根节点的 `font:` 简写，标题按 1.35em、代码块按 0.95em 等比跟随 |
| JSON 预览 | 重声明 JSON 树根节点的 `font:` 简写 |

宿主的这几处根节点都用 `font:` 简写把字号写死，而简写会一次性重置字号、字重与行高——外层容器上的 `font-size` **继承不进去**。这正是 v0.3.19 之前"预览里点字号按钮毫无反应"的原因：规则都在、看着都对，但被简写压掉了。现在每个根节点各自重新声明字号，并连带声明行高，否则放大后行会互相重叠。

这类"规则存在但赢不了层叠"的问题无法靠断言规则文本来防住，因此 `test/cascade.test.mjs` 用真实 Chrome 计算最终字号：把宿主样式表放在插件样式表**之前**（对插件最不利的顺序），再读取 `getComputedStyle` 的实际结果。没有 Chrome 的环境会跳过这三条而不是假装通过。

左边缘手柄也支持键盘：聚焦后 `←` / `→` 每次 ±16px（按住 Shift 为 ±64px），`Home` 到最小宽度，`End` 到窗口宽度。

手机端（宽度 ≤ 960px）与全屏模式下抽屉已经铺满可视区域，左边缘手柄自动隐藏。

手机端抽屉占满全屏，文件列表与内容单列切换（左上角 `‹` 返回列表）。

### 桌面版标题栏避让

两个桌面平台的窗口都有系统绘制的按钮区，且永远盖在页面之上，所以抽屉顶部必须从它们下方开始。两端用**不同的宿主标记**，不要用 UA 或窗口尺寸去猜平台：

| 平台 | 宿主标记 | 避让高度 | 行为 |
| --- | --- | --- | --- |
| Windows 桌面版 | `html[data-windows-titlebar]` | `--dsh-windows-titlebar-height`（默认 40px） | 抽屉从右上角最小化/最大化/关闭按钮下方开始 |
| macOS 桌面版 | `html[data-platform="darwin"]` | `--dsh-frame-overlay-top` → 回落 `--dsh-frame-top-clearance`（48px） | 抽屉从左上角交通灯按钮下方开始 |
| 全屏（任一平台） | `html[data-fullscreen]` | 偏移撤销 | 条带/交通灯隐藏，抽屉贴到顶边，不留死区 |
| Web 浏览器 | 无上述标记 | 无偏移 | 没有系统按钮要让位 |

Windows 端读宿主变量而不是写死 40px：125% / 150% 缩放下条带会变成 50 / 60px，写死就会错位（已按 40 / 50 / 60 / 80 四档验证）。

macOS 端按规范**优先消费宿主算好的 `--dsh-frame-overlay-top`**——宿主已经把平台与全屏状态折进这个值，插件再自己拼一套判断只会多出一个需要同步的口径。变量缺失时回落到原始的 `--dsh-frame-top-clearance`，两者都没有则不加任何偏移（凭空造一条偏移会变成点不到的死区）。

两条偏移都带 `!important`：抽屉为退出宿主"居中卡片化"而声明的 `inset:0!important` 会展开出同样重要的 `top:0`，普通声明赢不过它——这正是该问题在 v0.3.6 之后复发的原因。

**验证方式**：`test/package.test.mjs` 锁住规则文本、`!important` 与选择器特异性，并把"新出现的、会设置抽屉垂直几何的 `!important` 规则"列为必须人工复核的白名单；`test/cascade.test.mjs` 进一步在真实 Chrome 里测量抽屉头部的最终坐标——四种平台/全屏组合逐一断言，`elementFromPoint` 确认工具栏按钮在最上层可点击。规范见仓库根目录 `AGENTS.md` 的「桌面版兼容」一节。

手机端不需要这条偏移：抽屉在手机上占满全屏，而 `dsh-mobile-adapter` 会把含 scrim 的 overlay 层提到 `z-index:1100`（高于它自己 900 的顶栏），所以抽屉工具栏不会被顶栏压住。这两点由插件测试之外的因素保证，改动移动端层级时需一并复查。

### 桌面版圆角：抽屉是"卡片"，不是"浮层"

Windows 桌面版的抽屉与宿主内容卡**从同一条边开始**——标题栏条带的下沿。宿主把内容卡的**左上角**切 16px 圆角（`--dsh-windows-content-radius`），其余三个角保持直角。抽屉如果四角全直，就会在这条共用边上与内容卡拼成一条连续横带：会话标题、会话页签和抽屉工具栏连成一片，抽屉看起来像是**盖在窗口之上的一层**，而不是**窗口里的一块面板**——这正是"层级比窗体和会话高太多"的视觉来源。

因此 Windows 桌面版下抽屉只切**左上角**，取值直接消费宿主变量：

```css
html[data-windows-titlebar]:not([data-fullscreen]) .fv-shell[data-mobile="false"]{
  border-radius:var(--dsh-windows-content-radius,16px) 0 0 0}
```

- **只切一个角**：四角全圆会变成"悬浮卡片"，那是与窗口的另一种关系；右侧和底部贴住窗口边缘，保持直角。
- **消费宿主变量而非写死 16px**：宿主按 DPI 换算，写死会在 150% 缩放下错位。
- **全屏撤掉**：全屏时条带消失、抽屉铺满 frame，圆角会在窗口边缘留下缺口，所以用 `:not([data-fullscreen])` 收口。
- **不带 `!important`**：这条规则不与标题栏偏移争夺同一属性，留在普通声明里，也就不会进"必须人工复核"的白名单。

| 平台 | 抽屉圆角 |
| --- | --- |
| Windows 桌面版（窗口态） | 左上角 `--dsh-windows-content-radius`，其余直角 |
| Windows 桌面版（全屏） | 四角直角 |
| macOS 桌面版 | 四角直角（交通灯让位由 `top` 偏移负责，几何与 Windows 不同） |
| Web 浏览器 | 四角直角（没有需要对齐的宿主内容卡） |

**验证方式**：`test/cascade.test.mjs` 在真实 Chrome 里读取 `getComputedStyle` 的四个角，逐平台/全屏组合断言最终半径，并验证改宿主变量时圆角跟着变（证明消费的是变量而不是字面量）；`test/package.test.mjs` 锁住"只切左上角"与"不带 `!important`"。移除该规则后这两项测试即失败。

## Git 面板

左侧栏顶部有两个页签：**文件**（目录树）与 **Git**（源代码管理）。Git 页签按 VSCode 源代码管理面板的方式组织：仓库 → 分支 → 提交记录 → 该提交的改动文件。

- **仓库识别**：当前根目录本身是仓库时直接读取它；根目录不是仓库、但一级子目录里有仓库时，逐个列出（例如一个工作区下并列多个项目）。根目录位于某个仓库内部（工作区是仓库的子目录）时，读取的仍是那个仓库，且只能打开根目录以内的文件——其余文件在列表里标为「根目录外」并禁用。
- **分支**：下拉框按「本地分支 / 远程分支」分组，只切换**查看哪条分支的历史**；右侧「检出」按钮才会真正执行 `git checkout` 改写工作区，两者分开以避免误触。远程分支（`origin/xxx`）标注为**只读**，检出按钮禁用——检出远程分支只会得到游离 HEAD 或悄悄新建本地分支，不是用户以为的切换。工作区有未提交改动、git 拒绝检出时，面板直接给出「工作区有未提交的改动，无法切换分支」，不会静默失败。
- **工作区改动**：面板上部常驻工作区变更列表，按 VSCode 的习惯分成**冲突 / 已暂存 / 未暂存 / 未跟踪**四组；同一个文件既暂存又再修改时标「部分暂存」。点击任一条目在右侧显示该文件的 diff，可暂存/未暂存两侧切换；未跟踪文件没有 diff，按「整文件都是新增」渲染。
- **提交记录**：按 30 条一页加载，显示标题、短 SHA、作者与日期，底部「加载更多」按需追加，并显示「已显示 N / 总数」。
- **改动文件列表**：点击任一提交，右侧显示该提交的完整信息（标题、完整 SHA、作者、时间、正文）与相对**第一父提交**的改动文件列表（合并提交同理；根提交与空树比对）。`A / M / D / R / C` 等状态用颜色区分。
- **该提交的 diff**：提交详情有「变更文件 / 改动内容」两个页签，后者是该提交针对同一基准（第一父提交）的完整 patch，按文件分段并各自标注 `+N -M`。两个页签取的是同一对 revision，不会出现列表与 diff 基准不一致的情况。
- **跳转到文件**：点击改动文件会在右侧已有的预览器里打开**该提交中的版本**，而不是工作区当前内容——两者恰恰在历史最有价值的时候不同。被该提交删除的文件从父提交读取，所以删除行也能打开；重命名显示旧路径的内容。预览顶部会标明来源提交，避免被误认为当前文件。`‹` 返回 「变更文件」列表继续浏览。

  打开后有两个页签：**改动**（这个提交对该文件做了什么，默认显示）和**完整内容**（该版本文件的全文，可翻页、切换语法高亮）。重命名的 diff 会保留为「重命名」而不是退化成「删除 + 新增」——宿主端把新旧两侧路径一起交给 git，否则 `-M` 无法配对。

只读操作（列出仓库、分支、历史、改动文件）不会修改仓库；面板中唯一的写操作是用户显式点击「检出」。

### 边界与安全约束

- **检出范围**：如果当前根目录只是某个仓库的**子目录**（仓库在上级），检出会一并改写根目录以外的文件。面板会先显示醒目提示，并在执行前要求确认；宿主端在未收到显式同意时直接拒绝（`checkout-outside-root`），不会默认放行。
- **仓库探测上限**：为控制开销，子目录探测最多 32 个候选目录。达到上限时面板明确提示「列表可能不完整」，而不是静默返回一个看似完整的空列表。
- **环境隔离**：每次调用 `git` 都会剥离 `GIT_DIR`、`GIT_WORK_TREE`、`GIT_INDEX_FILE` 等变量，避免宿主进程环境把命令重定向到根目录以外的仓库；检出时用 `-c core.hooksPath=` 禁用仓库 hooks，不会执行用户仓库里的脚本。
- **错误如实上报**：`git` 不存在报 `git-unavailable`，diff 失败报 `git-failed`，都不会伪装成「没有仓库」或「没有改动」。

Git 页签在首次打开时才请求仓库信息（识别仓库需要对子目录做 `git` 探测），切换根目录会丢弃已缓存的仓库与历史；刷新会保留正在浏览的分支。

## 访问边界与安全访问路径

插件**内置可访问**所有**已注册的工作区目录**以及**各会话的工作目录**。

如需让文件查看器访问工作区以外的目录或磁盘，可通过配置**安全访问路径**（`safePaths`）放开指定路径的访问权限：

```yaml
- id: file-viewer
  name: dsh-file-viewer
  config:
    # 安全访问路径列表（支持字符串路径，或带展示标签的对象）
    safePaths:
      - /opt/data
      - /var/log
      # 支持自定义标签：
      # - path: /data/share
      #   label: 共享数据盘
      # Windows 示例：
      # - D:/Notes
    # 在线预览（图片/PDF/表格/文档）单文件上限，默认 20 MB
    maxBytes: 20971520
    # 下载到本地单文件上限，默认 100 MB
    maxDownloadBytes: 104857600
```

配置后：
- 在文件查看器顶部的工作区下拉框中，将分组呈现「工作区」与「安全访问路径」，可直接切换浏览；
- 在对话回复或工具调用中点击属于安全访问路径内的文件路径时，文件查看器会自动定位并直接打开预览；
- 每次请求都会先规范化路径，再用 `ctx.fs.contains` 严格校验目标落在工作区或已配置的安全访问路径之内，严防 `..` 目录穿越与符号链接逃逸；
- 为保持向后兼容，原有的 `extraRoots` 与 `safeAccessPaths` 别名依然有效并会自动合并；
- **Web 界面动态配置与双重持久化**：可在输入框工具栏文件查看器入口或文件树顶部的「安全访问路径设置」弹窗中直接添加、查看或删除安全路径，保存后会自动双重持久化写入当前 Profile 配置（`cordis.patch.yml`）与本地文件（`~/.dsh/file-viewer/settings.json`），DSH 服务重启后配置稳定保留不丢失。

### 下载与预览使用两套上限

下载上限（`maxDownloadBytes`，默认 100 MB）与在线预览上限（`maxBytes`，默认 20 MB）是**独立**的两个值，因为两条通道的代价不同：

- **预览**把整个文件以 base64 塞进 JSON 响应，浏览器还要再 `atob` 解码一次；20 MB 的文件已经会产生约 27 MB 的传输文本，因此这条通道刻意保持小预算；
- **下载**由浏览器直接消费，或由桌面端流式读取后交给保存流程，不需要解码进页面，因此可以给到 100 MB。

两个上限都支持通过配置调整；把 `maxDownloadBytes` 调大时，宿主仍需一次性读出该文件，请按可用内存权衡。

### 下载在不同宿主中的行为

插件在 `/api` 之下注册了一个带鉴权的流式下载端点，并让客户端按宿主能力选择传输方式：

- **浏览器**：先发一次 `HEAD` 预检（超限直接提示「文件超过下载限制（上限 100MB）」，不会产生一条失败的下载记录），随后把鉴权后的 URL 交给浏览器原生下载管理器。进度、暂停、续传与保存位置都由浏览器负责，页面内存不随文件大小增长；
- **桌面端（Electron）**：桌面外壳没有浏览器的下载面板，因此改用 `fetch` 流式读取，并在抽屉内实时显示百分比进度（如 `正在下载 dataset.zip (45% - 45.2 MB / 100.0 MB)...`），完成后交给保存流程；
- **兜底**：流式端点不可用（旧宿主或路由被占用）时，自动回退到既有的 RPC `bytes` 通道，功能不缺失。

下载端点的错误响应只回传机器可读的原因码（如 `FS_TOO_LARGE`、`too-large`），不会回显宿主的绝对路径；这与 RPC 通道既有的「绝不泄露路径」约定一致。

## 未知后缀文件的文本识别

后缀无法识别时（如 `config.yaml.prod`、`env.dev`、`env.staging`），宿主端不会直接判为二进制，而是**读取文件开头的 8 KB 采样窗口**做内容判断：

- 采样中**没有 NUL 字节**（与 git、`file(1)` 相同的启发式）；
- 且采样能**按 UTF-8 解码**（采样末尾被截断的多字节字符会被保留，不算错误）。

两者同时满足即按文本渲染。这样做有两个要点：

- 采样走 `ctx.fs.readByteRange`，**以窗口为界**而非以整个文件为界，因此 20 MB 的未知后缀文本文件也能正确识别，且宿主不会整体缓冲该文件；
- 若只判断 NUL 字节，GBK 等非 UTF-8 编码的文件会被误判为文本，然后在读取阶段失败；因此这里一并校验 UTF-8，识别不出时诚实报「不是 UTF-8 文本」而不是「读取失败，可能没有访问权限」。

## 语言格式识别与手动指定

后缀认不出时，插件不会止步于「按纯文本显示」：它会**按内容猜一次语言**，并把最终决定权交给用户。

### 语言是怎么定的

按以下优先级决定，先命中者胜出：

| 优先级 | 来源 | 说明 |
| --- | --- | --- |
| 1 | **用户指定** | 在下拉框里手动选定，记在本地，之后打开这个文件一直生效 |
| 2 | **文件后缀** | 已知后缀（`.py`、`.yaml`、`.go` …）比内容启发式更可靠 |
| 3 | **文件内容** | 后缀认不出时按内容判断 |
| 4 | 无 | 都不成立则按纯文本显示，不做高亮 |

### 内容识别的依据

只认**有明确特征**的内容，宁可不高亮也不猜错——猜错会让高亮落在语法并不期望的记号上，把文件染成误导性的颜色。识别规则按特异性从强到弱：

- **Shebang**：`#!/bin/bash`、`#!/usr/bin/env python3`、`#!/usr/bin/env node` 等，解释器直接写在第一行，最可靠；
- **精确首标记**：`<?xml`、`<!DOCTYPE html`、`\documentclass`、`syntax = "proto3";`、`resource "…" {`（Terraform/HCL）、`query Foo {`（GraphQL）；
- **JSON**：必须**真的能解析**才算，截断的采样不算证据（所以被截断的 JSON 不会被误判成 CSV）；
- **YAML / INI / CSV / Dockerfile**：要求结构证据——YAML 需要多数行是 `key: value` 且不出现 `=` 赋值；INI 需要至少一个 `[section]` 或三条以上赋值；CSV 需要两行以上且**列数一致**（单行含逗号太常见，不足以判定）；Dockerfile 需要以 `FROM` 开头且其余行都是合法指令。

### 手动指定

打开文件后，标题栏右侧会出现语言下拉框，**自动**为默认项：

- 选任意语言即固定高亮，选择**按文件路径**记忆（不是按后缀），所以同一个 `.prod` 后缀下不同文件可以各自不同；
- 选**纯文本**可关掉高亮；
- 选回**自动**即清除记忆，回到上面的自动判定；
- **识别来源看 tooltip**：把鼠标停在语言下拉框上会显示「语法高亮：TypeScript（按后缀识别）」。括号里说明当前语言是**按后缀识别**、**按内容识别**还是**未识别**，让你能分辨「这是猜的」还是「这是确定的」；手动指定过的文件显示「已指定」。

识别来源**不再作为常驻文字**显示在工具栏上。那段文字宽度随来源变化，会让文件大小与语言下拉框左右跳动，同一排控件在不同文件之间忽宽忽窄；放进 tooltip 后工具栏是一排固定宽度的控件，信息也没有丢失。

下拉框的选项来自宿主端（`languages` RPC），与宿主校验用的同一份目录，因此界面不可能给出宿主不接受的选项；提交的指定也会在宿主端重新校验，未知 id 一律忽略并回落到自动判定。

## 已知限制

- 文件列表不显示修改时间：`ctx.fs` 的目录项只提供名称、类型与大小。
- 工作区需要手动选择：宿主端不存在"当前活跃工作区"的概念，该状态只在前端 UI 中。
- 大表格截断到 2000 行 × 64 列。
- Word 转换保留标题、强调、列表与表格，复杂排版与图片会降级。
- 文本识别只看开头 8 KB：文件开头是 UTF-8 文本、之后才出现非 UTF-8 字节时，仍会在读取阶段报「不是 UTF-8 文本」。
- 文件树中的图标按名称判断（只有图片后缀显示图片图标），实际能否预览以打开后的元数据为准。
- 内容识别也只看开头 8 KB（`meta` 阶段）；打开文件时 `read` 已持有全文，会用全文再判一次，因此特征出现在 8 KB 之后的文件在打开后仍能正确高亮。
- 语言指定只记在本机浏览器（localStorage），不跨设备同步；上限 200 条，超出后淘汰最旧的。
- 语言下拉框只对源码类视图（文本 / Markdown / JSON）显示；图片、表格、文档没有语法可指定。
